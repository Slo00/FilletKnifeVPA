# ADR-003: ручные оверрайды рекомендаций — аннотации на VPA, применяет recommender, пишет веб-интерфейс

## Статус

Принято, 2026-09-19.

## Контекст

Recommender переписывает `status.recommendation` каждый цикл, поэтому ручное
значение, записанное в статус поверх него, исчезнет через минуту. Оверрайд должен
обрабатываться **внутри** recommender'а.

Нужно, чтобы владелец сервиса мог посмотреть рекомендацию рядом с исходными
`requests`/`limits` из манифеста и текущим потреблением, выставить свои значения,
зафиксировать, что recommender их применяет, и вернуть сервис в автопилот.
В самом VPA должно быть видно, кто и когда это сделал.

## Решение

**Хранение — аннотации на самом объекте VPA** (префикс `vpa-override.kubernetes.io/`,
как у существующего `vpa-post-processor.kubernetes.io/`). Recommender и так читает
`vpa.Annotations` (`model.Vpa`), новая CRD и дополнительные права не нужны.
Формат и разбор — один пакет `pkg/recommender/override`, его используют и recommender,
и веб-интерфейс.

| Аннотация | Смысл |
|---|---|
| `mode` | `Pinned` или `Paused`. Нет аннотации — Auto. Остальные ключи без неё игнорируются |
| `resources` | JSON `{"<контейнер>": {"cpu": "700m", "memory": "300Mi"}}`, только для `Pinned`, cpu и memory оба обязательны |
| `set-by`, `set-at` | кто и когда |
| `expires-at` | **обязателен**; после него возврат к расчёту |
| `reason` | свободный текст |

**Режимы** (`routines/override.go`, `processVPAUpdate`):

- `Pinned` — в `status.recommendation` идут заданные значения; target, lowerBound
  и upperBound равны заданному. Так updater сразу подхватывает поды с другим request
  (он вне коридора `[lower, upper]`) и не трогает поды, которые уже совпали. Если
  закреплены все контейнеры, расчёт не выполняется — пин не зависит от доступности VM.
  Закреплён лишь часть контейнеров — остальные считаются как обычно.
- `Paused` — VPA пропускается, `status.recommendation` остаётся как есть.
- Auto — расчёт.

**Срок обязателен и проверяется при чтении.** Просроченный оверрайд — это Auto. Оверрайд
без срока или с любым другим дефектом — тоже Auto, с ошибкой в логе: то, что нельзя
прочитать, не должно превращаться в забытое исключение. Recommender сам аннотации
не чистит (ему не нужны права на запись метаданных): просроченные остаются до очистки
из интерфейса.

**Расчёт для сравнения.** Recommender не кладёт «то, что я бы посчитал» никуда:
веб-интерфейс сам считает его по запросу тем же кодом (`victoriametrics.NewRecommenderFromConfig`
с теми же флагами), поэтому числа совпадают с recommender'ом.

**Веб-интерфейс** — отдельный сервис ([Slo00/FilletKnifeVPA-WebUI](https://github.com/Slo00/FilletKnifeVPA-WebUI)),
единственный, кто пишет оверрайды.
Имя автора берётся из заголовка, который выставляет SSO-прокси перед ним; без
имени запись запрещена. Установка и снятие оверрайда дополнительно фиксируются
событиями Kubernetes на VPA (снятие иначе не оставило бы следа).

## Последствия

- Закреплённые значения не проходят расчётный минимум (`--pod-recommendation-min-*`):
  человек задал их явно. Глобальные потолки (`--container-recommendation-max-allowed-*`)
  и цепочка постпроцессоров действуют как раньше.
- Пин работает, только если updater вообще применяет рекомендации: при
  `updateMode: Off` значения попадут в статус, но не в поды. Интерфейс это показывает.
- **Лимиты не задаются оверрайдом.** Их считает admission-controller: сохраняет пропорцию
  `limit/request` из исходного манифеста (`GetProportionalLimit`,
  `pkg/utils/vpa/limit_and_request_scaling.go`). Интерфейс показывает эту пропорцию и получившийся лимит.
- Кто угодно с правом `patch` на VPA может поставить оверрайд в обход интерфейса — в этом
  случае `set-by` не гарантирует подлинность. Авторизацию по namespace/классу
  критичности интерфейс пока не делает.
- Аннотации лежат в объекте VPA: при перечитывании статуса лишних запросов нет,
  но история изменений — только в событиях Kubernetes (по умолчанию живут около часа).

## Альтернативы

Отдельная CRD отклонена: схема и валидация были бы строже, но нужны новая CRD, RBAC
и код в контроллере, а аннотации закрывают потребность без этого.
Запись значения прямо в `status.recommendation` отклонена: перезатирается на следующем цикле.
